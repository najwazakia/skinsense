# SkinSense — Frontend

This repository contains the user interface (frontend) for **SkinSense**, an AI-powered skin disease detection platform. Built with **Next.js 16** and **React 19**, the application provides a complete user experience from uploading a photo and receiving AI analysis, to viewing detection history and participating in a community discussion forum.

> ⚠️ **Disclaimer:** Detection results from this application are not a substitute for a professional medical diagnosis. Always consult a dermatologist for proper treatment of your skin condition.

## Key Features

- **Skin Disease Detection** — Upload a skin photo via drag & drop or file picker and receive an AI classification result with a confidence score and top-3 predictions.
- **AI Recommendations (Gemini)** — Every detection result is accompanied by a condition description, treatment advice, over-the-counter medication suggestions, and warnings generated by Google Gemini.
- **Detection History** — Users logged in with Google can view their full history of past skin analyses in a card grid with confidence badges and progress bars.
- **Discussion Forum** — A community forum for discussing skin conditions. Supports creating threads, commenting, editing/deleting posts, and an upvote/downvote system.
- **Dual Authentication Mode** — Anonymous users (not logged in) can use the detection feature. A Google login is required to access history and the forum.

## Prerequisites

Make sure the following are available before getting started:

- **Node.js** v18 or later
- **npm** or another package manager (yarn/pnpm)
- A running SkinSense backend server (see the [backend repository](https://github.com/your-org/skin-detection-server))

## Installation & Setup

**1. Clone the repository**
```bash
git clone https://github.com/your-org/skin-disease-detection.git
cd skin-disease-detection
```

**2. Install dependencies**
```bash
npm install
```

**3. Configure environment variables**

Create a `.env.local` file in the project root. You can use `.env.example` as a reference:

```env
# Cloudinary
NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME=your_cloud_name
NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET=your_upload_preset

# Firebase Auth
NEXT_PUBLIC_FIREBASE_API_KEY=your_api_key
NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN=your_project.firebaseapp.com
NEXT_PUBLIC_FIREBASE_PROJECT_ID=your_project_id
NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET=your_project.firebasestorage.app
NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID=your_sender_id
NEXT_PUBLIC_FIREBASE_APP_ID=your_app_id
NEXT_PUBLIC_FIREBASE_MEASUREMENT_ID=G-XXXXXXXXXX

# Backend Server URL
NEXT_PUBLIC_API_BASE_URL=http://localhost:5000
```

> All variables prefixed with `NEXT_PUBLIC_` are exposed to the browser. Do not store any secrets here.

**4. Start the development server**
```bash
npm run dev
```

The application runs at `http://localhost:3000`.

**5. Build for production**
```bash
npm run build
npm start
```

## Usage Guide

### 🔍 Skin Disease Detection

1. Open the home page (`/`).
2. Upload a skin photo by **dragging and dropping** it onto the upload area, or click the area to select a file from your device.
   - Supported formats: JPG, PNG (max. 10 MB).
   - For best results, ensure the photo is clear, well-lit, and focused on the skin area you want to analyze.
3. The application automatically runs three sequential steps:
   - **Upload** — the image is sent to Cloudinary.
   - **Analysis** — the AI model classifies the skin condition.
   - **Recommendation** — Gemini generates an explanation and treatment advice.
4. You will be redirected to the **Analysis Result** page (`/result`), which displays:
   - The detected skin condition and its confidence score.
   - The top-3 predictions from the model.
   - AI recommendations in four sections: description (`deskripsi`), treatment (`penanganan`), over-the-counter medication (`obat_bebas`), and warnings (`peringatan`).

> Detection can be performed without logging in. However, history is only saved for users logged in with Google.

---

### 📋 Detection History

1. Log in with your Google account via the **"Sign in with Google"** button in the header.
2. Navigate to the **History** page (`/history`).
3. All past detection results are displayed in a grid of cards, each showing the image, condition label, a color-coded confidence badge (green ≥ 80%, yellow ≥ 60%, red < 60%), a progress bar, and the relative time of analysis.

---

### 💬 Discussion Forum

The forum is only accessible to users logged in with Google.

**Browsing & searching threads:**
- Open `/forum` to view all discussions.
- Use the search bar to filter threads by title.

**Creating a new thread:**
- Click the **"New Post"** button on the forum page.
- Fill in the title and content, add tags (optional), and upload an image (optional).

**Inside a thread:**
- View the thread content along with its upvote and downvote counts.
- Cast a vote using the 👍 / 👎 buttons.
- Write a comment in the input field at the bottom (press `Ctrl+Enter` to submit).
- If you are the thread author, **Edit** and **Delete** buttons are available next to the author name.
- Your own comments can also be edited or deleted.

## Authentication System

The application uses two Firebase authentication modes simultaneously:

| Mode | Condition | Access |
| :--- | :--- | :--- |
| **Anonymous** | User is not logged in — a session is created automatically by Firebase | Skin detection (history not saved) |
| **Google OAuth** | Logged in via Google popup | Detection + history + full forum access |

When the app is first opened, Firebase automatically creates an anonymous session in the background. This session is persisted in the browser's IndexedDB, so it survives page refreshes. When a user logs in with Google, the anonymous session is upgraded to a Google session without any additional action required.

> **Note:** If Firebase Anonymous Authentication is not enabled in your Firebase project, the app will gracefully handle the `auth/operation-not-allowed` error — the `anonAuthDisabled` flag in `AuthContext` will be set to `true` and detection features may be limited.

## Detection Flow (Internal)

The `useDetection` hook orchestrates the following three steps in sequence:

```
1. Upload to Cloudinary  →  receives image_URL & cloudinary_public_id
            ↓
2. POST /detection        →  AI model classifies the image, result saved to DB
            ↓
3. POST /detection/recommendation  →  Gemini generates the recommendation
            ↓
   Redirect to /result    →  data temporarily stored in sessionStorage
```

The result data (`detectionResult`, `recommendation`, `resultImageUrl`, and `previewUrl`) is stored in `sessionStorage` to transfer between pages. If `sessionStorage` is empty when `/result` is opened, the user is automatically redirected back to the home page.

## API Proxy

`next.config.ts` sets up a server-side proxy rewrite so that all client requests to `/api/*` are forwarded to the backend server, stripping the `/api` prefix:

```
/api/:path*  →  NEXT_PUBLIC_API_BASE_URL/:path*
```

This means you do not need to configure CORS on the backend for development, and the client never calls the backend directly.

## Next.js Configuration

The `next.config.ts` file allows images to be loaded from the following remote domains:

| Domain | Purpose |
| :--- | :--- |
| `lh3.googleusercontent.com` | Google account profile photos |
| `res.cloudinary.com` | Uploaded images from detection & forum |

If a new image domain needs to be supported, add it to the `remotePatterns` array in `next.config.ts`.
